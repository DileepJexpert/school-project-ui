**Findings — P1 denotes the original high priority; P2 denotes a functional defect. Items 3–6 are fixed in the current working tree.**

1. **[P1] Settings logout does not end the session.** [lib/features/admin/screens/settings_screen.dart:164](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/admin/screens/settings_screen.dart:164) removes only the persisted access token. It leaves AuthService's in-memory user/token, the stored user, and the refresh token. Log out here, then navigate to the admin URL without restarting: the route guard still considers the user authenticated. A subsequent 401 can use the retained refresh token to restore an access token. Use the same AuthService.logout() path as the sidebar, clear session state centrally, and remove protected navigation history. This differs from the sidebar's correctly centralized logout.

2. **[P1] Passwords, tokens, and school records are logged in release builds.** [lib/services/dio_client.dart:76](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/services/dio_client.dart:76) unconditionally installs a logger with request and response bodies enabled; request headers are enabled by default. Login passwords, bearer tokens, refresh tokens returned by login, student records, and submitted AI configuration can reach the console. A local synthetic-data probe confirmed password and bearer-token disclosure. Disable body/header logging in release and redact secrets in development logs.

3. **[P1, fixed] Attendance previously allowed a stale roster to be saved under another class, year, or date.** [lib/features/admin/screens/attendance_screen.dart:54](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/admin/screens/attendance_screen.dart:54) now enables submission only for the loaded context. Changing any of those filters clears the roster; a late response for a superseded load is discarded. The save request uses the captured loaded context.

4. **[P1, fixed] Marks entry previously retained the roster after a class or year change.** [lib/features/admin/screens/results_admin_screen.dart:202](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/admin/screens/results_admin_screen.dart:202) now binds the roster and submission to the loaded class/year. Changing either filter clears marks and rows, late loads are discarded, and an earlier successful save cannot clear a newer roster's marks.

5. **[P1, fixed] Fee collection previously carried payment details between students.** [lib/features/admin/screens/fee_collection_screen.dart:67](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/admin/screens/fee_collection_screen.dart:67) now resets discount, mode, remarks, cheque details, and transaction reference on selection, close, and successful payment. Discounts are validated before submission, and mode-specific references are sent only for the matching payment mode.

6. **[P1, fixed] A failed attendance read previously created an all-present register.** [lib/features/admin/screens/attendance_screen.dart:185](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/admin/screens/attendance_screen.dart:185) now displays the read error and leaves submission disabled. A successful empty response remains the only path that initializes a new all-present register.

7. **[P2] Results publishing duplicates the API prefix.** [lib/services/result_api_service.dart:108](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/services/result_api_service.dart:108) passes /api/results/publish to a Dio client whose configured base already ends in /api. Using the installed Dio package, a local probe produced http://localhost:8080/api/api/results/publish. Both the default configuration and Netlify configuration use that base convention. Change the service path to /results/publish and add a request-URI assertion.

8. **[P2] Mobile navigation bypasses the frontend role restrictions.** [lib/features/admin/admin_dashboard_page.dart:298](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/admin/admin_dashboard_page.dart:298) always renders Fees and Admissions and selects those screens directly. The sidebar uses AuthService.canAccessMenu(), but this navigation path and _buildContent() do not. A teacher or transport manager on a narrow viewport can open modules hidden from their desktop menu. Build all navigation from the same allowed-item list and guard content selection. This proves a client-side access-control inconsistency; server-side unauthorized access cannot be established without the backend.

9. **[P2] Attendance includes enquiries and inactive students.** [lib/features/admin/screens/attendance_screen.dart:157](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/admin/screens/attendance_screen.dart:157) filters the complete student list only by class, ignoring status and academic year. Elsewhere, StudentApiService.getAllStudents() is explicitly filtered to exclude ENQUIRY in the Students screen, demonstrating that this service can return those records. An enquiry or departed student in the class is offered for marking and defaults to PRESENT. Restrict the roster to enrolled students for the selected academic year.

10. **[P2] Authentication retries have no terminal condition.** [lib/services/dio_client.dart:55](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/services/dio_client.dart:55) refreshes on every 401 and retries through the same interceptor without a retry marker. If refresh succeeds but the protected endpoint continues returning 401, the retry enters another refresh/retry cycle instead of returning an error. Limit each request to one retry, share one refresh across concurrent failures, and transition to logged-out state when recovery fails. The separate refresh client also omits X-Tenant-ID; verify that contract against the backend.

11. **[P2] Video upload can never select a file.** [lib/features/admin/screens/video_management_screen.dart:239](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/admin/screens/video_management_screen.dart:239) defines both picker helpers as stubs that return null. The dialog requires fileBytes before enabling Upload, so clicking the picker cannot make upload reachable. Implement the picker and cancellation/error handling, then exercise upload with a small video.

12. **[P2] The student video player does not play videos.** [lib/features/student_portal/screens/my_videos_screen.dart:166](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/student_portal/screens/my_videos_screen.dart:166) renders an icon, label, and selectable stream URL rather than a media element/controller. Selecting a video never starts playback. The suggested new-tab URL also bypasses Dio's bearer and tenant headers, so whether that workaround works depends on the absent backend's stream authorization. Implement actual playback with a supported authentication mechanism.

13. **[P2] Saving an API URL never changes the API client.** [lib/features/admin/screens/settings_screen.dart:73](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/admin/screens/settings_screen.dart:73) writes api_base_url and says restarting applies it, but [lib/services/dio_client.dart:9](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/services/dio_client.dart:9) uses only String.fromEnvironment. No client initialization reads the saved setting. The settings form can also show localhost while the compiled deployment points elsewhere. Either support one validated runtime configuration source consistently across HTTP/auth/media, or display the build-time URL as read-only.

14. **[P2] Loading the timetable twice fails in debug mode.** [lib/features/admin/screens/timetable_screen.dart:60](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/admin/screens/timetable_screen.dart:60) disposes and recreates TabController on each successful load while the State uses SingleTickerProviderStateMixin. Flutter's installed mixin asserts on the second ticker creation even if the first was disposed. Load twice, or save a day and trigger the reload, to hit this condition. Initialize the fixed six-day controller once or use TickerProviderStateMixin. This specific assertion is a debug-mode defect, not a claim of a release-build crash.

15. **[P2] Failed chat sends silently discard the user's text.** [lib/features/chat/chat_screen.dart:59](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/chat/chat_screen.dart:59) clears the input before awaiting the POST and suppresses the exception. If the send fails, the message is absent from history and cannot be retried from the UI. Retain the draft until success or restore it on failure, and show a retryable error.

16. **[P2] Invalid marks are silently converted to real zero scores.** [lib/features/admin/screens/results_admin_screen.dart:298](C:/Users/dileepkm/OneDrive/ドキュメント/School-project/lib/features/admin/screens/results_admin_screen.dart:298) accepts every nonempty field and converts a failed numeric parse to 0.0; maxMarks similarly defaults to 100. Typing an invalid value can therefore submit a valid-looking zero and lose the distinction between invalid input and an actual score of zero. Require finite numeric marks within 0..maxMarks and a positive finite maximum before submission.

**Other completeness and maintenance gaps**

- There is no test/ or integration_test/ suite and no analysis_options.yaml enabling the declared flutter_lints package. Prioritize regression coverage for the P1 workflows before cosmetic lint cleanup.
- Parent Chat is explicitly “Coming Soon”; the existing ChatListScreen is not connected to that menu. PaymentGatewayService has no callers, so online payment checkout is not implemented in the UI.
- Admission form downloads only show a snackbar; the home page's “Apply Now” and “Discover More” buttons have empty callbacks. Certificate generation lists metadata but exposes no download/print action.
- Settings saves school_name locally, but the initial field and public identity use AppStrings.schoolName; the saved value is not read to render them.
- Async lifecycle handling is inconsistent. For example, StudentsScreen._loadStudents() calls setState after requests without checking mounted, while dashboard menu changes dispose the previous screen. Navigating away during a slow request can produce setState-after-dispose errors. Audit request cancellation, mounted checks, and stale-response protection across administration screens.
- Fee setup and expense entry accept nonempty, nonnumeric amounts and coerce them to zero. Fee collection accepts negative/oversized discounts without a frontend validation error. Backend financial validation remains unverified.
- Academic-year formats differ: admissions and fee structures use YYYY-YYYY, while attendance/results use YYYY-YY, with several old default years. Parent/student result and fee DTOs also differ from administrative models. These require backend contract comparison; differing frontend shapes alone are not proof of a server mismatch.
- The repository supports a web target only in its current layout. Unconditional dart:html imports in Settings and CSV export, and missing Android/iOS platform directories, do not support the README's mobile quick-start claims.
- Generated .dart_tool files are tracked despite the ignore rule, making environment-dependent changes appear in source control.
